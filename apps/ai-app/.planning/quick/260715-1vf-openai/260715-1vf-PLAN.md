  <action>
  Make the service standalone and introduce shared infrastructure used by every route (Claude discretion aligned with recommended gateway scope).

  1. In `package.json`: rename `name` to `openai-gateway` (or `ai-app` if preferred for folder clarity — pick `openai-gateway`); remove dependency `@ai-food/shared-types` entirely (no workspace protocol left); keep existing express/openai/zod/multer/cors/dotenv deps.
  2. Create `src/types.ts` inlining only what analyze-food and the error contract need: `ApiError` (`message`, `code`, `status`), `NutritionResult`, `AnalyzeFoodResponse`. Do not re-import from `@ai-food/shared-types` anywhere.
  3. Create `src/lib/openai.ts` exporting `getOpenAIClient()` that constructs `OpenAI` with `process.env.OPENAI_API_KEY` and a 30s timeout (reuse the behavior currently inlined in analyze-food). Fail fast with a clear thrown Error or mapped ApiError if the key is missing when a route needs the client.
  4. Create `src/lib/errors.ts` with `sendApiError(res, status, code, message)` writing the `ApiError` JSON body, plus `mapOpenAIError(error)` returning `{ status, code, message }` for at least: RateLimitError → 429 `RATE_LIMITED`; APIConnectionTimeoutError → 504 `UPSTREAM_TIMEOUT` (analyze-food may keep domain code `ANALYSIS_TIMEOUT` when mapping locally for that route, but shared mapper uses `UPSTREAM_TIMEOUT` for v1); BadRequestError → 400 `BAD_REQUEST`; else → 500 `UPSTREAM_ERROR`. Never leak the OpenAI secret or full raw SDK dumps to clients.
  5. Create `src/middleware/api-key.ts`: if `process.env.API_KEY` is unset/empty, call `next()`. If set, accept either Authorization Bearer token matching API_KEY or header X-API-Key with the same value; on mismatch/missing respond 401 with code `UNAUTHORIZED` via `sendApiError`.
  6. Extract `createApp()` into `src/app.ts`: cors, `express.json({ limit: '10mb' })` (vision payloads can be large), mount `GET /health` BEFORE api-key middleware so health stays open, apply api-key middleware to the rest of the app, leave mounting of analyze-food and `/v1` routers for Task 2 (or mount stubs empty routers if needed for compile). `src/index.ts` only loads dotenv, calls `createApp()`, listens on `PORT` (default 3001).
  7. Update `.env.example` with `OPENAI_API_KEY`, `PORT`, and optional `API_KEY` with a one-line comment that omitting it disables gateway auth.

  Do not add new npm packages. Do not build a full OpenAI REST clone beyond the planned routes.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller apps → gateway HTTP | Untrusted JSON/multipart; optional shared API_KEY |
| Gateway → OpenAI API | Trusted egress with server-held OPENAI_API_KEY |
| Process env → runtime | Secrets must not appear in responses or logs beyond necessary errors |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1vf-01 | Information Disclosure | src/lib/openai.ts, error handlers | high | mitigate | Keep OPENAI_API_KEY server-side only; ApiError responses use opaque codes/messages; never echo API keys |
| T-1vf-02 | Spoofing | src/middleware/api-key.ts | high | mitigate | Optional API_KEY via Bearer or X-API-Key; 401 UNAUTHORIZED when configured and missing/wrong |
| T-1vf-03 | Elevation of Privilege / Abuse | /v1/chat/completions, /v1/embeddings | medium | mitigate | Gateway auth when API_KEY set; non-streaming-only chat reduces long-lived proxy abuse surface |
| T-1vf-04 | Denial of Service | multer + express.json | medium | mitigate | 10MB multer and JSON body limits; 30s OpenAI timeout |
| T-1vf-05 | Tampering | Zod validation on v1 bodies | medium | mitigate | Reject invalid chat/embeddings payloads with VALIDATION_ERROR before calling OpenAI |
| T-1vf-SC | Tampering | npm installs | low | accept | No new packages in this plan; existing lockfile deps unchanged except removing workspace package |
</threat_model>
