## Architecture (executor must follow)

Prefer **one abstract base + six thin subclasses + six receivers** (picker clarity, per suggested approach):

| Action token | Subclass | Meta-data XML | Picker label string |
|--------------|----------|---------------|---------------------|
| `scan` | `ScanWidgetProvider` | `widget_scan_info.xml` | existing / short picker name |
| `scan-describe` | `ScanDescribeWidgetProvider` | `widget_scan_describe_info.xml` | … |
| `gallery` | `GalleryWidgetProvider` | `widget_gallery_info.xml` | … |
| `describe` | `DescribeWidgetProvider` | `widget_describe_info.xml` | … |
| `manual` | `ManualWidgetProvider` | `widget_manual_info.xml` | … |
| `favorites` | `FavoritesWidgetProvider` | `widget_favorites_info.xml` | … |

Base class owns: layout inflate, set icon+label on RemoteViews, single click PendingIntent to `aifood://add/{action}` with `MainActivity`, same flags as current `AddFoodWidgetProvider` (`NEW_TASK|CLEAR_TOP`, `UPDATE_CURRENT` + `IMMUTABLE` on M+). Unique `requestCode` per action (e.g. 1001–1006) so PendingIntents do not collide.

Reuse existing vector drawables (`ic_widget_camera`, `ic_widget_pen`, `ic_widget_gallery`, `ic_widget_keyboard`, `ic_widget_star`) and colors (`widget_*`). Do not add new npm packages.

|----------|-------------|
| Launcher → AppWidget receiver | System delivers APPWIDGET_UPDATE; app builds PendingIntents |
| Widget tap → MainActivity | Untrusted only in the sense of fixed app-owned URIs; no user text |
| MainActivity → WebView/JS | Existing Capacitor deep-link path parses allowlisted actions |
