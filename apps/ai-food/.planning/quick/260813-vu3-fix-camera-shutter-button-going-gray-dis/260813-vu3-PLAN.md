## Root cause (confirmed in code)

1. Shutter `disabled={Boolean(cameraError) || capturing}` (ScanPage ~558) goes busy on `setCapturing(true)` at the start of `handleShutter`.
2. Food path then `await captureVideoFrame` → offscreen canvas `toBlob('image/jpeg', 0.92)` at `AI_IMAGE_MAX_SIDE` (1024). On Android WebView this callback often lands 0.5–2s later. Meanwhile the rAF loop (`cameraActive && !cameraError` only — capturing is not in the condition) keeps `drawVideoContain` from a still-playing `<video>`. Symptom: busy shutter + live preview.
3. Food success never calls `setCapturing(false)` / `unlock()` (createCaptureLock stays busy until unmount/navigate). That is intentional against double-submit, but the visual mismatch exists for the whole toBlob window because preview is not frozen.
4. Barcode shutter sets capturing true around detect and clears it in `finally`, but also leaves the rAF loop painting live frames — same mismatch for the detect duration.

- pages/scan/index.ts barrel (still exports only ScanPage). Helper stays slice-internal via relative import like captureVideoFrame.
- No new npm packages. No apps/ai-app changes.
