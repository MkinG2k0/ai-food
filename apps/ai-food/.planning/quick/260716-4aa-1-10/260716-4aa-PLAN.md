## Locked decisions (honor exactly)

- **D-01 Source:** Values come from AI food analysis response, then persist on the Meal entity.
- **D-02 Display:** Two ranges AFTER the date line on Meal Detail («Детали приёма»). Date lives in `MealSummaryEditor` CardHeader (`formatDate` + time) — put ranges there, not in page chrome.
- **D-03 Fields:** (1) healthiness / полезность — integer scale 1–10; (2) recognition accuracy / точность — percent 0–100 derived from existing `confidence` (0.0–1.0) via `Math.round(confidence * 100)`.
- **D-04 Labels:** Russian «Полезность», «Точность».
- **D-05 Legacy:** If `healthiness` or `confidence` is undefined on Meal, omit that row (and omit the whole block if both missing). Do not invent defaults.
- **D-06 UI:** Range-style bars consistent with existing `MacroBar` / `NutritionRow` (h-1.5 muted track + filled bar), muted text under the date — not bare numbers only.

## Already in codebase (reuse — do not redesign)

- `NutritionResult.confidence: number` (0–1) + validators in analyze/refine + backend Zod
- `NutritionCard` already shows `{confidencePct}% совпадение` on result screen — leave as-is unless types break fixtures
- Mobile live path is client AI Gateway (`analyzeFoodApi` / `refineMealApi`); backend route still exists — keep schemas in sync per D-01

## Discretion (documented choices)

- **Field names on Meal:** optional `healthiness?: number` and `confidence?: number` (mirror NutritionResult; display converts confidence→%). Do not add a separate `recognitionAccuracy` field.
- **healthiness on NutritionResult:** required number 1–10 (same strictness as fiber/confidence for new AI responses). Fixtures in tests must include it.
- **Out of scope:** ResultPage NutritionCard redesign; MealCard list UI; manual editing of these scores; migration of old diary rows.

## Patterns

- FSD: types in `@ai-food/shared-types`; cross-slice imports via barrels
- Co-located Vitest fixtures: every NutritionResult mock must gain `healthiness`
- Russian copy; 2-space indent; single quotes
