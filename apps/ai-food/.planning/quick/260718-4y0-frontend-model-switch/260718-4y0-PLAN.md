## Architecture facts (must follow)

- Mobile AI calls go to `VITE_AI_GATEWAY_URL/v1/chat/completions` (often local backend `:3001`). Backend mounts the proxy at `/v1/chat/completions` and holds `OPENROUTER_API_KEY`.
- Today `chat-completions.ts` ignores `body.model` and always uses `getOpenRouterModel()` — that must change: client model wins when provided.
- Normalize accepted client models with existing `toOpenRouterModel()` from `apps/backend/src/openrouter.ts`.
- Fallback: missing/blank `body.model` → `getOpenRouterModel()` (env `OPENROUTER_MODEL` or default `openai/gpt-4.1-mini`).
- Persist selection in existing `useSettingsStore` (`ai-food-settings` + capacitorStorage). Do not invent a new store.
- Keep API key on backend only. Do not add OpenRouter secrets to mobile env beyond the existing gateway key pattern.
- Russian UI copy for Settings. Cross-slice imports via FSD barrels only.

## Out of scope

- Changing multipart `POST /analyze-food` (mobile food AI uses chat/completions, not this route).
- New npm dependencies; auth; model pricing UI; free-text arbitrary model input (use a fixed curated list).
- Backend package legitimacy / new packages.
</context>
