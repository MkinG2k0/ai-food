<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client (browser) → Express backend | Multipart image upload crosses here; client is untrusted |
| Express backend → OpenAI API | API key and base64 image leave the backend here |
| OpenAI API → Express backend | JSON response crosses here; model output is untrusted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | OPENAI_API_KEY | mitigate | Key loaded via dotenv from apps/backend/.env; never in Vite build; never returned in any API response; console.error logs error objects not the key |
| T-02-02 | Denial of Service | multer file upload | mitigate | Add `limits: { fileSize: 10 * 1024 * 1024 }` (10MB) to multer config: `multer({ storage: multer.memoryStorage(), limits: { fileSize: 10 * 1024 * 1024 } })` — prevents memory exhaustion from oversized uploads |
| T-02-03 | Tampering | OpenAI JSON response | mitigate | Zod schema (`NutritionResultSchema`) validates all fields before use; extra fields are stripped; `JSON.parse` wrapped in try/catch; model output never passed to eval/exec |
| T-02-04 | Tampering | multer req.file missing | mitigate | Explicit `if (!req.file)` guard before any buffer access; returns INVALID_IMAGE (400) |
| T-02-05 | Spoofing | OpenAI error responses | mitigate | Raw OpenAI error messages are logged via `console.error` only; client receives generic `ApiError` shape with no internal details |
| T-02-06 | Denial of Service | OpenAI API timeout | mitigate | `timeout: 30_000` in OpenAI client constructor; `APIConnectionTimeoutError` mapped to ANALYSIS_TIMEOUT (504) with fast client-side feedback |
| T-02-07 | Information Disclosure | TypeScript build output | accept | `dist/` is not deployed in MVP; no secrets in compiled JS; `dist/` in .gitignore |
</threat_model>
