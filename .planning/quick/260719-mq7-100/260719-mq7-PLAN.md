## Locked product decisions (this quick task)

**D-01 — Persistence:** Keep `FoodItem` as absolute portion nutrients + `grams`. Do not add per-100 fields to shared types or localStorage.

**D-02 — Formula:** `portionNutrient = sanitizeNutrient(per100 × grams / 100)`; reverse `per100 = sanitizeNutrient(portion × 100 / grams)` when `grams > 0`.

**D-03 — UI:** On `FoodItemEditPage`, add a clear section titled «На 100 г» with the same five macros (Ккал, Б, У, Ж, Кл). Keep existing absolute portion inputs; label that group «На порцию» (or equivalent short Russian) so the two groups are distinguishable.

**D-04 — Bidirectional sync:**
- Edit per-100 → write all five absolute nutrients for current grams via `updateMealItem`.
- Edit grams → rescale absolute nutrients from current density (equivalent to `new = old × newGrams / oldGrams` when oldGrams > 0; if oldGrams is 0, apply `nutrientsFromPer100` using displayed/derived per-100 if available, else leave nutrients unchanged).
- Edit absolute portion → do not store per-100; display derives per-100 live from D-02.
- Include fiber in every direction.

**D-05 — Override of 260716-24h D-06 (edit page only):** Previously grams edits did not touch macros. On `FoodItemEditPage` only, grams edits now rescale macros using density (D-04). Do not change `updateMealItem` store semantics elsewhere; other screens that call `updateMealItem({ grams })` alone stay unchanged unless they adopt the same helper.

**D-06 — Sanitization:** Reuse `sanitizeNutrient` / `sanitizeGrams` / `resolveItemGrams` / `formatItemGrams`. No NaN/Infinity in inputs or store.

## Out of scope

- Changing `FoodItem` / `NutritionItem` types
- AI prompts, save/refine mapping, meal-level totalGrams redistribution
- New npm dependencies; backend; other pages
