## Locked decisions (do not reopen)

**D-01 — AI flow:** correction text → AI Gateway → NutritionResult → `updateMeal` with name, items, totalCalories.

**D-02 — Button placement:** below `MealSummaryEditor`, above «Состав».

**D-03 — UI:** BottomSheet + Textarea patterned after `AddFoodSheet` describe mode (title, placeholder, primary submit).

**D-04 — Client gateway only:** use `VITE_AI_GATEWAY_URL` / `VITE_AI_GATEWAY_API_KEY` like `analyzeFoodApi`; do not change `apps/backend` (decision 260716-05y).

**D-05 — Image preference:** if meal has `imageUri` and image bytes load, include image + correction; else text-only refine with current meal name/items as context.

**D-06 — UX feedback:** loading state on sheet submit button; `toast.success` / `toast.error` (sonner) on outcome.

**D-07 — Feature slice:** new `features/refine-meal` (not edit-meal) for cohesion; public API via barrel `index.ts` only.

## Architecture facts (must follow)

- `analyzeFoodApi(image: File)` is image-only today — add a **separate** refine export; do not break existing image analyze callers/tests.
- `useSaveMeal({ description })` does **not** call AI — do not reuse it for refine.
- Meal images: `saveMealImage` / `getMealImageSrc` / Filesystem under `meal-images/`; for gateway prefer a `data:image/...;base64,...` URL built from Filesystem.readFile (web path in `getMealImageSrc`), not Capacitor convertFileSrc URIs.
- Keep `FoodItem.grams` number semantics; map AI items with `resolveItemGrams`.
- Reuse exported `FOOD_NAME_PROMPT_RULE` and `COMPOSITION_PROMPT_RULE` from `analyzeFoodApi.ts` in the refine prompt.
- Apply result via `updateMeal(id, { name, items, totalCalories })` — leave timestamp/imageUri/status unchanged unless status was error (then set ready on success).

Backend changes; new npm deps; Auth; changing AddFoodSheet / useSaveMeal description path; manual item edit flows; Profile/onboarding.
