# Quick Task 260818-28i: Referral system — Context

**Gathered:** 2026-08-18
**Status:** Ready for planning

<domain>
## Task Boundary

User referral program across `apps/ai-app` (billing/auth/prisma) and `apps/ai-food` (Settings UI + existing subscribe promo field).

- Logged-in user has a shareable promo code (Telegram nick, or fallback).
- Referee enters that code on `/subscribe` (same field as admin promos) → **10% off**.
- Referrer gets **+30 days** of access **only after the referee's payment is confirmed**.
- Settings: copy button + count of paid conversions (no Telegram PII).

Out of scope: admin analytics for referrals, custom user-typed codes, stacking two codes, showing the block on `/subscribe`.
</domain>

<decisions>
## Implementation Decisions

### D-01 Code identity (auto)
Promo is created automatically after login. No «Создать промокод» button. Code = normalized Telegram username (no `@`, lowercase, same as `normalizePromoCode`).

### D-02 No Telegram username (fallback)
If `username` is missing, assign a stable fallback: `u` + last 8 alphanumeric chars of `user.id` (lowercase). Persist on `User.referralCode` (unique). If username appears later, switch `referralCode` to the nick (old fallback stops matching). If the nick collides with an admin `PromoCode`, keep/use the fallback instead.

### D-03 Referrer reward
On **confirmed** payment that used a referral code (not an admin catalog code): add **30 days** to the referrer.
- If referrer has no subscription or it is expired: `subscriptionStatus=active`, `expiresAt = now + 30d`.
- If referrer has an active license: extend `subscriptionExpiresAt` by 30 days from the current expiry.
Grant even if the referrer never bought (user locked). Idempotent: one grant per confirmed payment (do not double-fire on webhook + sync).

### D-04 Conversion counter
Settings shows a **count only** — number of **confirmed** payments that used this user's referral code. No Telegram names/ids/usernames of referees.

### D-05 One promo field (admin first)
Existing `/subscribe` field. Resolve: admin `PromoCode` first; else matching `User.referralCode` at 10% off. Cannot apply two codes. Unknown code → existing `INVALID_PROMO`.

### D-06 UI placement
Own code + copy + conversion count **only in Settings** (Account section). Guest: no code; existing «Войти». Logged-in without username still sees fallback code.

### D-07 Auth gate
No referral code / share UI without login. Applying a referral at checkout still requires an authenticated subscriber (existing billing JWT). Block **self-referral** (cannot use own `referralCode`).

### D-08 Copy
Copy-to-clipboard button next to the code in Settings.

### Claude's Discretion
- Exact API path (`GET /user/referral` vs `/billing/referral`) — prefer JWT-gated, FSD `features/referral` or extend billing.
- Prisma: `User.referralCode` unique + grant bookkeeping (flag on Payment vs small `ReferralGrant` table) — pick the simpler idempotent option.
- Fallback collision if 8-char suffix clashes: retry with more of the id.
- Copy feedback: short toast «Скопировано».
</decisions>

## Specific Ideas

- Today: `PromoCode` admin catalog + `Payment.promoCode`; `resolvePromo` only hits catalog; `activateYearLicense` **replaces** expiry with paidAt+duration (does not extend). Referral month must **extend**, not replace, the referrer's expiry; referee still gets normal year via `activateYearLicense`.
- Hook all confirm paths: T-Bank notification, `/billing/sync`, `/billing/mock/confirm`.
- Assign/refresh `referralCode` on Telegram (and demo) login upsert.
- Do not commit unrelated dirty files (`android/`, `dist/`, nutrition-report WIP).
