# Quick Task 260813-0w7: Аналитика стабильности и скорости сервера ai-app в ai-web - Context

**Gathered:** 2026-08-13
**Status:** Ready for planning

<domain>
## Task Boundary

Reliability dashboard for `apps/ai-app` (gateway) surfaced in `apps/ai-web` admin: **E = A + B**.

- **A:** Latency & error trends from existing `GatewayRequest` (volume, error rate, p50/p95 duration/TTFB over days, by type where useful)
- **B:** Live server health (full set)

UI: new admin page `/admin/health`.

Out of scope: alerts/SLOs, external APM (Sentry/OTel), full HTTP middleware metrics for all routes (option C).

</domain>

<decisions>
## Implementation Decisions

### Product scope
- Variant **E**: combine GatewayRequest trends (A) + live process/DB health (B)

### UI placement
- Separate page: `/admin/health` in `apps/ai-web` (nav entry in admin shell)
- Do not overload overview or requests page as primary surface (requests page can stay as-is for drilldown)

### Health metrics (v1 = full)
- uptime
- DB ping latency (ms) + reachability
- status: `ok` / `degraded`
- RSS / heap memory
- event-loop lag

### Latency / stability trends (A)
- Built on existing `GatewayRequest` + `/admin/stats` / series patterns
- Charts: daily volume, error rate, p50/p95 duration (and TTFB if cheap to add)
- Window: align with existing admin series (e.g. 7 days default)

### Claude's Discretion
- Exact API shape (`/admin/health` live + reuse/extend stats series vs new endpoints)
- Degraded thresholds (e.g. DB ping / event-loop lag cutoffs)
- Chart library / layout consistency with existing `SparklineCard` + Ant Design admin
- Whether public `/health` stays minimal and detailed metrics are admin-only (prefer admin-only for memory/lag details)

</decisions>
