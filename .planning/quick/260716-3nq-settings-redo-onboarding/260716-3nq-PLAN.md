## Architecture facts (must follow)

- Onboarding data lives in `useProfileStore` (`ai-food-profile`): `profile: UserProfile | null`, `targets: DailyTargets | null`. Fields: gender, age, height, weight, activity, goal — **no separate diet-type field** in onboarding (diet prefs stay in Settings `customInstructions`).
- `/onboarding` is unguarded; `/settings` is behind `ProfileGuard`. Clearing profile while on Settings makes `isComplete()` false → guard redirects to `/onboarding`. Still call `navigate('/onboarding', { replace: true })` after reset for explicit UX.
- Cross-slice imports only via FSD barrels (`@/features/onboarding`, `@/shared/ui`).
- Russian UI. Reuse `BottomSheet` + `Button` pattern from `DeleteMealConfirmSheet` (inline confirm in SettingsPage is fine — no new feature slice required unless it stays clean).
- No new npm deps. Do not touch backend or shared-types shapes.

## Out of scope
