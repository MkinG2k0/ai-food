## Architecture decision: route, not modal

No Dialog/Modal primitive exists in `apps/mobile/src/shared/ui/` (only Button, Card, Badge, Skeleton) and `@radix-ui/react-dialog` is not in `apps/mobile/package.json` -- only `@radix-ui/react-slot` is installed. Adding a Dialog would mean pulling in a new dependency and building/testing a new accessible primitive as a side effect of a quick task, which the constraints explicitly steer away from ("no new heavy dependencies").

The codebase already has an established pattern for this exact interaction: `MealList`'s "View All" button already does `navigate('/diary')` for a summary-to-detail transition, and the router already wraps every route in `ProfileGuard`. A new `/meal/:id` route reuses that pattern exactly, requires zero new dependencies, and trivially satisfies "identical behavior from HomePage and DiaryPage" since both call the same `navigate()`.

Decision: add a `pages/meal-detail` page + `/meal/:id` route. `MealCard` (in `entities/meal`) gets an `onClick` that calls `useNavigate()` -- this keeps the click behavior inside the entity's own presentation (entities may own presentation per FSD) without entities importing from pages/features; the entity only depends on `react-router-dom`, a third-party lib, which is allowed at any layer.
</context>
