# Phase quick-260706-x79 Plan 01: Show detailed meal info on MealCard click Summary

**MealCard is now clickable everywhere it renders and opens a new `/meal/:id` route showing every FoodItem with its own macros/portion, summed meal-level protein/carbs/fat, full date+time, and total calories — computed entirely from existing `Meal`/`FoodItem` data with no new dependency.**

## Accomplishments
- `MealCard` root `Card` gained `onClick`/`onKeyDown` navigation to `/meal/${meal.id}`, plus `role="button"`, `tabIndex={0}`, `aria-label`, and `cursor-pointer` for accessibility — identical behavior whether rendered from `MealList` (HomePage) or `DiaryPage`.
- New `pages/meal-detail` FSD slice with `MealDetailPage`: reads `id` via `useParams`, selects the meal from `useDiaryStore`, sums protein/carbs/fat across `meal.items` via `.reduce`, and renders per-item cards plus aggregate `NutritionRow`s.
- New `/meal/:id` route registered in `router.tsx`, wrapped in `ProfileGuard` like every other route.
- Stale/invalid meal id (URL tampering or diary cleared) redirects to `/diary` via `useEffect` + `navigate(..., { replace: true })` instead of crashing on `undefined.items`.

## Decisions Made
- Route over modal: no `Dialog` primitive exists in `shared/ui`, and `@radix-ui/react-dialog` isn't installed — adding one would introduce a new dependency for a quick task. The existing `navigate('/diary')` pattern (used by `MealList`'s "View All" button) was reused instead.
- Meal-level protein/carbs/fat are computed on the fly via `.reduce` over `meal.items` in `MealDetailPage`, since `Meal` has no meal-level macro fields — matches the plan's explicit instruction not to invent a field that doesn't exist in the type.
- Back button in `MealDetailPage` navigates to `/diary` (not `history.back()`), matching the plan's guidance that `/diary` is the "canonical" full view regardless of which list (Home or Diary) the user clicked from.
