## Locked (D-01 … D-09)

- Hit metric is daily summed meal.totalCalories of ready meals only. Profile rings / other macros are out of this streak (D-01).
- Export CALORIE_STREAK_TOLERANCE = 0.20 from entities/streak. All bounds use this constant (D-02).
- G = nutrition profile targets.kcal. P = CALORIE_STREAK_TOLERANCE. goal from profile.goal: gain hits when kcal >= G * (1 - P); maintain hits when G * (1 - P) <= kcal <= G * (1 + P); lose hits when kcal <= G * (1 + P). Example G=2000: gain 1820 and 2500 hit; lose upper 2200 (D-03).
- A local date with no ready meal never hits, including 0 kcal. Analyzing/error-only days do not create a ready meal (D-04).
- Strip today from calorie hit keys before the freeze walk. Calorie length never includes the still-open local day. Walk therefore starts at yesterday, same helper as logging (D-05).
- Same StreakSheet. Second week row stacked under logging week. Labels «Запись» and «Норма». No second sheet, no route. DailyHeader Flame chip stays logging currentLength (D-06).
- Friends list row and friend profile show logging streak and calorieStreak. sortFriendsByStreakDesc still uses logging streak only (D-07).
- Nested persist calorieStreak: freezeCount 0..2, consumedFreezeDateKeys, grantedMilestones, bestStreak, currentLength. Grants +1 at first 7/14/30/60/100 under cap. Logging consumed dates never cover a calorie gap (D-08).
- Extend existing clientStreak JSON on POST /user/streak/sync. Friends read calorieStreak.currentLength from that JSON. No new Prisma column, no new route (D-09).

## Calorie algorithm (executor: implement exactly)

G from useProfileStore.targets.kcal. goal from useProfileStore.profile.goal. If either is missing or G is not a finite number greater than 0, calorie track is empty (length 0, no new freeze consume/grant).

Per localDateKey: sum totalCalories of meals with (status ?? 'ready') === 'ready'. Hit if that sum is greater than 0 and D-03 bounds pass for goal (D-01 D-04).

Calorie counted set = hit keys minus localDateKey(now) (D-05). Pass that set into the existing computeCurrentRun / longestHistoricalRun / computeGrant / buildWeekDays, using persist.calorieStreak freeze fields instead of the logging ones. Do not copy-paste a second walk; extract shared helpers in computeStreak.ts if they are still file-private.

Freeze yesterday-while-today-open behavior comes for free: today is never in the calorie counted set, so todayCounted is false and the existing yesterday-gap break applies.

Grant milestones stay [7, 14, 30, 60, 100]. Milestone 3 is display-only for the calorie next-goal card too.

bestStreak for calorie = max(persisted calorie best, current calorie length, historical covered run on calorie keys + calorie consumed dates).

shouldCelebrate stays logging-only. Do not auto-open the sheet for a calorie hit.
