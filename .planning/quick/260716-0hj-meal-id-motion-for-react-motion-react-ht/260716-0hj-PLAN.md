## Architecture decisions (locked + discretion)

**D-locked-1 — Detail delete:** кнопка удаления на MealDetailPage (`/meal/:id`).

**D-locked-2 — Swipe + confirm:** свайп в списке → только диалог подтверждения; удаление только после подтверждения.

**D-locked-3 — Motion:** использовать Motion for React. В проекте уже `framer-motion@^12.42.0`; WeekStrip и BottomSheet импортируют из `framer-motion`. Импортировать `motion` / `animate` / `PanInfo` из `framer-motion` (эквивалент Motion for React). Не добавлять пакет `motion`, если `framer-motion` уже покрывает API. Если executor проверит что `motion/react` резолвится из установленного пакета — допустимо; иначе оставить `framer-motion` как в WeekStrip.

**D-locked-4 — Store:** только `useDiaryStore.getState().removeMeal` / selector `removeMeal` — без backend API.

**D-locked-5 — FSD:** свайп и оркестрация удаления — в `features/delete-meal`, не внутри entity `MealCard`. `MealCard` остаётся презентационной карточкой. Списки (`MealList`, `DiaryPage`) подключают `SwipeableMealCard` из фичи через barrel.

**Discretion — Confirm UI:** не `window.confirm`. Переиспользовать существующий `BottomSheet` из `@/shared/ui` (паттерн как в `AddFoodSheet`) — без нового Radix Dialog и без новых зависимостей.

**Discretion — Toast:** после успешного удаления можно вызвать `toast` из `sonner` с русским текстом (Toaster уже в providers); не обязательно для done, но желательно.

**Out of scope:** calendar-date баги, AI gateway, clearDiary, правки backend.
